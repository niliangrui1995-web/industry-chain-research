## 数据读取方法

主数据源：

`D:\vcp_hunter\紫金研选\data\vcp_hunter.db`

读取 SQLite 表 `kv_store` 中 `key='earnings_state'` 的 JSON。JSON 通常包含 `last_sync_date`、`seen`、`records`，从 `records` 中读取业绩异动记录。

按北京时间 `now` 计算过去 24 小时窗口，优先使用每条记录的 `发现时间` 或 `discovered_at` 过滤；这些字段按 Asia/Shanghai 解释。若缺少发现时间，只能用 `揭晓日` / `公告日期` / `源公告日期` 和 `kv_store.updated_at` 作为 fallback，并在报告或最小运行状态中标注 `time_filter_fallback=true`。

字段兼容：

| 语义 | 字段 |
|---|---|
| 股票代码 | `股票代码` / `代码` |
| 股票名称 | `股票名称` / `股票简称` / `名称` |
| 报告期 | `报告期` |
| 类型 | `数据类型` / `类型` |
| 揭晓日 | `揭晓日` / `公告日期` / `源公告日期` |
| 环比 | `环比增速_百分比` / `环比%` |
| 同比 | `同比增速_百分比` / `同比%` |
| 当季利润 | `单季净利润_新增` / `当季利润` |

与 UI 展示口径对齐：

- 剔除名称包含 `ST`、`*ST` 的记录。
- 同一 `股票代码 + 报告期` 去重，保留最新 `发现时间`。
- 若同日多类型并存，优先级为 `财报 > 快报 > 预告`，并说明覆盖关系。

代码规范化：

- `600xxx.SH`
- `688xxx.SH`
- `000xxx.SZ`
- `002xxx.SZ`
- `300xxx.SZ`
- `301xxx.SZ`

无法判断交易所时，保留 6 位代码并标注。

若 `vcp_hunter.db` 或 `earnings_state` 不存在/不可读，尝试只读 fallback：导入 `D:\vcp_hunter\紫金研选\domains\earnings\engine.py` 中的 `EarningsEngine().get_cached_records()`，优先使用 `D:\vcp_hunter\紫金研选\.venv\Scripts\python.exe`。

若 fallback 仍失败，停止并报告 `earnings_state_unreadable`，不要编造股票列表。

## 存在新增股票时的证据原则

1. 紫金研选业绩异动 Tab 只作为触发器和初筛，不作为最终事实来源。
2. 官方披露优先：CNINFO 巨潮、SSE、SZSE、BSE、公司公告、定期报告、业绩预告、业绩快报、投资者关系记录。
3. 第三方财经数据和媒体只能作交叉验证或行情上下文。
4. 每家公司必须找到与 `报告期 + 类型 + 揭晓日/源公告日期` 匹配的官方公告或官方披露页面；找不到时，仍可做初评，但必须标注 `official_disclosure_status=not_found` 并降低信心。
5. 对业绩预告、快报、财报分开判断：预告重在区间、原因、扣非、一次性；快报重在营收、利润、资产负债等主要指标和后续修正风险；财报重在完整报表、现金流、毛利率、费用、库存、应收、分部和审计/问询风险。
6. 涉及最新价格、市值、PE/PB、换手率、涨跌幅、龙虎榜、封板、市场反应时，必须用当前行情/交易数据工具或可信公开行情核对，并标注时间戳。行情只用于交易弹性和市场反应，不得证明基本面。
7. 不给买卖指令、目标价、仓位建议；只给研究优先级、证据强弱、含金量和跟踪点。

## 每家公司分析流程

仅在存在新增股票时执行：

1. 身份核对：上市主体、ticker、交易所、主营业务、主要产品/服务、所属产业链位置。
2. 官方公告核验：公告标题、公告日期、报告期、数据类型、原文链接、关键财务指标、业绩变动原因、是否预审计/审计、是否有更正或修正风险。
3. 基本面快速体检：业务质量、竞争位置、客户/下游需求、毛利率与费用趋势、现金流、应收/存货、资产减值、一次性收益、周期位置、治理和披露质量。
4. 含金量判断：区分 `核心业务增长`、`产品/价格/订单驱动`、`结构性改善`、`低基数恢复`、`一次性收益`、`会计/公允价值/投资收益`、`成本下降`、`减值冲回`、`补贴/处置收益`、`证据不足`。
5. 三层结论分开：基本面质量、业绩弹性、交易弹性。不要把业绩高增直接等同于好公司，也不要把股价强度当作业绩含金量。
6. 打分建议：含金量 `高 / 中 / 低 / 证据不足`，并给 `confidence=high/medium/low`。可以附 0-100 辅助分，但必须解释扣分项。
7. 后续跟踪：列出 2-4 个后续验证指标，例如正式财报落地、扣非口径、现金流、订单/客户、毛利率、应收存货、修正公告、投资者交流、市场预期差。

## 输出与写回

仅在存在新增股票时执行。

在 `D:\vcp_hunter\产业链投研\artifacts\earnings_movement\` 下写入：

- `YYYY-MM-DD.md`：当日业绩异动含金量分析日报。
- `run_status.md`：本轮运行状态、数据窗口、读取来源、命中数量、失败项。

日报结构必须包含：

- 运行元数据：北京时间、24 小时窗口、数据源、命中数量、官方核验覆盖率。
- 结论先行：含金量最高、最值得继续深研、最像一次性/低基数、证据不足名单、最大共性风险。
- 总表：ticker、name、类型、报告期、揭晓日、环比、同比、当季利润、公告状态、含金量、基本面质量、业绩弹性、交易弹性、下一步。
- 单公司卡片：官方证据、核心财务变化、业绩原因拆解、基本面判断、含金量判断、风险、跟踪指标。

如果新增公司超过 10 家：

- 必须先完成全部公司的总表初评；
- 再深挖含金量最高或风险最大的前 10 家；
- 其余写入“待补深挖”并说明原因，不能静默遗漏。

最终对话摘要保持简短：命中数量、最高含金量公司、低含金量/一次性风险、证据缺口、报告路径。不要粘贴整篇日报。
