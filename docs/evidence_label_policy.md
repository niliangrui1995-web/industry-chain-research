# 证据标签规范

Last verified: 2026-06-25

本规范用于后续新增或更新的报告、公司卡片、事件记录和周度跟踪。历史产物不批量回写；只在被重新审阅或新增结论时补齐标签。

## 标签

| Label | 含义 | 可支持的结论 |
|---|---|---|
| `official_disclosure` | 公司公告、年报、季报、招股书、官方新闻稿或法定披露。 | 公司事实、财务数据、业务范围、产能、风险提示。 |
| `exchange_filing` | 交易所、CNINFO、SEC、HKEX、TDnet、MOPS、DART 等披露系统。 | 公告状态、监管文件、交易公开信息、正式披露时间。 |
| `company_ir` | 公司官网 IR、业绩会、投资者关系记录、IR 日历或官方 webcast。 | 公司口径、管理层表述、客户/产品进展的公司侧说法。 |
| `market_data_vendor` | TDX、iFinD、HT/TongDaXin、本地行情包、第三方行情 API。 | 价格、估值、换手、技术状态、交易弹性和市场反应。 |
| `web_model_lead` | Grok、Gemini、网页模型、社交搜索或模型整理的线索。 | 线索池、观察池、待核验方向；不能单独成为硬结论。 |
| `secondary_media` | 可信媒体、研报、行业机构、供应链调研或数据库转述。 | 背景、交叉验证、行业趋势和待验证假设。 |
| `observation` | 证据不足但值得跟踪的现象、邮件线索、市场误读或弱信号。 | watch / observation / event trade，不升级为客户、订单、收入或毛利证明。 |

## 日期与来源

- 每条关键结论至少保留 `source_date` 或 `checked_at`。
- 行情、估值、涨跌幅、换手率和技术指标必须写明数据日期或交易日。
- 网页模型和社交线索必须标明采集窗口，例如最近 24/48/72 小时。
- 没有公开可见来源时写 `source_gap` 或 `N/A`，不要沿用旧值冒充新证据。

## 升级规则

- `web_model_lead`、`secondary_media` 和 `observation` 只能进入线索池，不能单独升级为正式公司事实。
- 客户、订单、收入、毛利率、产能、供货资格和直接受益人，需要 `official_disclosure`、`exchange_filing` 或 `company_ir` 支撑。
- `market_data_vendor` 只能证明市场状态或交易弹性，不能证明真实受益、客户关系或订单。
- 多来源冲突时，先保留冲突描述和证据标签，不用弱来源覆盖强来源。
- 结论分层保持为基本面质量、业绩弹性、交易弹性、最大风险点和后续跟踪指标。
