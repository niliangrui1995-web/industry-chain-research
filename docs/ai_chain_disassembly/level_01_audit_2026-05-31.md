# AI 产业链逐级拆解 - Level 1 审计表

日期：2026-05-31

任务类型：审计

被审计文件：`docs/ai_chain_disassembly/level_01_from_data_center.md`

审计结论：不通过

下一任务：继续梳理 Level 1，不进入 Level 2。

## 结论先行

现有 Level 1 表已经覆盖了 AI 数据中心的主要价值池，但不满足“从数据中心向上游逐级拆解”的主目标，原因是它把三类不同口径混在了一张 Level 1 主表里：

1. 可逐级拆到 BOM、材料、设备和制造环节的硬件链；
2. 电力资源、并网、工程建设等外部约束或项目交付链；
3. 软件、运维、安全、测试等横向支撑链。

因此，本轮审计不允许进入 Level 2。下一轮应先修订 Level 1：主表只保留可继续向上游拆解的一级硬件/工程价值链；外部资源、软件运维、可靠性测试放入附表或横向约束表。

## 下一版 Level 1 修订约束

| rule_id | 约束 | 说明 |
|---|---|---|
| R1 | 主表只放可继续往上游拆的节点 | 每个 Level 1 节点必须能继续拆到 Level 2 的产品、材料、设备、工艺或服务。 |
| R2 | 主表和附表分离 | 电力资源、并网、软件运维、安全测试、合规、项目审批可以保留，但不要放在主链 Level 1。 |
| R3 | 计算链先定口径 | 下一版必须在“GPU/ASIC 为 Level 1”和“AI 服务器/机架级系统为 Level 1”之间做明确选择，并解释与用户示例的关系。 |
| R4 | 避免重复归属 | PSU、机柜、rack power、DCIM/BMS、测试服务等交叉项必须有唯一主归属，不能在多条链重复计数。 |
| R5 | 每个节点保留审计字段 | 下一版继续保留 `node_id`、`level`、`parent_node_id`、`node_name`、`定义`、`需求传导`、`Level 2 候选`、`边界`、`status`。 |
| R6 | 不做股票映射 | Level 1 未通过前，不进入股票、估值、交易弹性或瓶颈结论。 |

## 建议的下一版主表框架

此处不是替代梳理表，只是给下一轮“继续梳理 Level 1”使用的审计约束。

| suggested_group | 建议处理 |
|---|---|
| AI 加速计算链 | 必须拆清 GPU/ASIC/TPU、CPU/DPU、AI 服务器、机架级系统之间的层级关系。 |
| 高速网络与互连链 | 可作为 Level 1，Level 2 再拆交换机、NIC/DPU、光模块、铜互连、OCS/CPO。 |
| 存储与数据链 | 可作为 Level 1，但优先级低于计算和网络。 |
| 供配电设备链 | 可作为 Level 1，需明确设施供电、rack power 和服务器 PSU 的边界。 |
| 热管理/液冷链 | 可作为 Level 1，Level 2 分板级、服务器级、机柜级、园区级。 |
| 机柜与物理集成链 | 需要决定是独立 Level 1，还是并入 AI 服务器/机架级系统。 |
| 工程建设、电力资源、软件运维、安全测试 | 默认不放主表，放附表或横向约束。 |
